After a script install, the `primevpn` command is your control center. Run it with
no arguments for the interactive menu, or pass a subcommand for a one-shot action.

```bash
primevpn
```

## The `primevpn` management menu

The menu (items `0`–`27`) shows the panel/Xray status at the top, then:

| #     | Item                                   | What it does                                              |
| ----- | -------------------------------------- | --------------------------------------------------------- |
| 1     | Install                                | (Re)install from the remote script                        |
| 2     | Update                                 | Update to the latest **stable** release                   |
| 3     | Update to Dev Channel (latest commit)  | Update to the rolling `dev-latest` build                  |
| 4     | Update Menu                            | Update just the `primevpn` menu script                        |
| 5     | Legacy Version (Disabled)              | Upstream legacy installation is disabled in PRIMEVPN     |
| 6     | Uninstall                              | Remove PRIMEVPN (see below)                                  |
| 7     | Reset Username & Password              | Set new credentials; optionally disable 2FA               |
| 8     | Reset Web Base Path                    | Randomize the web base path                               |
| 9     | Reset Settings                         | Reset panel settings (your account is preserved)          |
| 10    | Change Port                            | Change the panel port                                     |
| 11    | View Current Settings                  | Show username, port, web base path, cert paths            |
| 12–14 | Start / Stop / Restart                 | Control the panel service                                 |
| 15    | Restart Xray                           | Reload only Xray-core                                     |
| 16    | Check Status                           | Service status                                            |
| 17    | Logs Management                        | View debug logs / clear logs                              |
| 18–19 | Enable / Disable Autostart             | Toggle start-on-boot                                      |
| 20    | SSL Certificate Management             | Let's Encrypt (domain or IP), custom paths, renew/revoke  |
| 21    | Cloudflare SSL Certificate             | DNS-01 wildcard cert via Cloudflare                       |
| 22    | Firewall Management                    | `ufw` install and port rules                              |
| 23    | SSH Port Forwarding Management         | Bind the panel to localhost and tunnel over SSH           |
| 24    | PostgreSQL Management                  | Install/migrate/manage PostgreSQL                         |
| 25    | Enable BBR                             | Toggle the BBR congestion-control sysctl                  |
| 26    | Update Geo Files                       | Update geoip/geosite data (Loyalsoldier, IR, RU)          |
| 27    | Speedtest by Ookla                     | Run an Ookla speed test                                   |
| 0     | Exit                                   | —                                                         |

Some of these have their own pages: [SSL certificates](/docs/config/ssl-certificates)
(items 20–21), [Security](/docs/operations/security) (IP limits, firewall),
[Reverse proxy](/docs/operations/reverse-proxy) and [Panel settings](/docs/config/panel)
(TLS), and [Database](/docs/reference/database) (PostgreSQL).

## CLI subcommands

For scripts and quick actions, `primevpn` also takes a subcommand directly:

| Command                    | Action                                              |
| -------------------------- | --------------------------------------------------- |
| `primevpn start` / `stop` / `restart` | Control the service                          |
| `primevpn restart-xray`        | Reload only Xray-core                               |
| `primevpn status`              | Show status                                         |
| `primevpn settings`            | Show current settings                               |
| `primevpn enable` / `disable`  | Toggle autostart on boot                            |
| `primevpn log`                 | Tail the debug log                                  |
| `primevpn update`              | Update to the latest stable release                 |
| `primevpn update-dev`          | Update to the rolling `dev-latest` build            |
| `primevpn legacy`              | Return an error; upstream legacy installation is disabled |
| `primevpn update-all-geofiles` | Update all geo files, restart if changed            |
| `primevpn migrate-db --dsn …`  | Migrate SQLite → PostgreSQL (see [Database](/docs/reference/database)) |
| `primevpn pgclient [ver]`      | Install or upgrade PostgreSQL client tools                |
| `primevpn install` / `uninstall` | Install / uninstall                               |

## Updating

- **Stable:** menu option **2** or `primevpn update`. Re-running the install script
  also updates in place.
- **Dev channel:** menu option **3** or `primevpn update-dev` — the rolling
  `dev-latest` per-commit build (not a stable release).
- **Legacy upstream versions:** disabled in PRIMEVPN; use the stable or dev channel instead.

Updating preserves your database and settings. Take a
[backup](/docs/operations/backup-restore) before a major-version jump.

<Callout type="info">
  Docker users update differently — pull the new image and recreate the
  container (`docker compose pull && docker compose up -d`) rather than using the
  `primevpn` update commands.
</Callout>

## Uninstalling

Menu option **6** or `primevpn uninstall`. It stops and disables the service, removes
the service unit, and deletes `/etc/primevpn/` and the install folder. If the panel
used a locally-installed PostgreSQL, it offers to purge that too (a separate,
irreversible confirmation).

<Callout type="warn">
  Uninstalling removes the database (`/etc/primevpn/primevpn.db`) and your configuration.
  [Back up](/docs/operations/backup-restore) first if you might need it.
</Callout>
